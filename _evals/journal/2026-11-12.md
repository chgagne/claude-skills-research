## Trace reading: why the skill writes fewer rows (W3 data, no new runs)

1. **Volume is chosen, not constrained.** All arms read the paper and write their rows in one large write
   (1.0 per run, skill arms; 0.8, bare). The skill's write is smaller (median 16-20k chars vs 25k bare; the
   largest in either arm is about 30k), so it is not hitting an output ceiling. The gate cuts 0.7-0.9 rows per
   run. The skill agent decides to write ~54 rows where the bare agent writes ~81.
2. **The gap sits outside the skill's rule set.** Levels: mechanics +9, style +11, framing +5, flow +2 per run
   for bare. Math/notation proposals 15.2 per run bare vs 3.3 (form/current). Of the 117 REAL clusters only
   the bare agent hit, a keyword sort of their reasons gives: semantic precision / other 38 (a model "cannot
   be reduced", "the model does not record anything", a misplaced citation, a title promising more than the
   section holds), tables/figures/captions 16, notation 15, ambiguity 14, one-name/terms 14, claim vs
   evidence 10, word choice 6, punctuation 4. About two thirds have no key in `style-defaults.md` (22 keys:
   none for notation, ambiguous reference, wrong word, caption/text agreement, or claim vs evidence).
3. Reading: "every style row cites a rule; no rule, no row" plus the rubric's taxonomy define a narrow defect
   space, and the agent stays inside it. The W3 form listed the same taxonomy, which is why it could not add
   coverage. The agents do know anchors spanning math are allowed, so the math gap is scope, not mechanics.

Caveat: the categorisation is a keyword sort with a hand check of examples, not a judged label.
